# Read-only multi-order addon

New files only; no existing Septona files or PartPUlse-ORD production code are modified. No schema changes, API writes, automatic approval or order status updates. The addon uses existing GET /api/auth/verify, GET /api/orders/:id and optional GET /api/suppliers. The editor remains a local draft generator.

Deploy orders-connected.html and order-import.js beside the existing Septona editor files under the dedicated frontend/purchase-orders directory. Open /purchase-orders/orders-connected.html after logging into PartPulse on the exact same origin. Existing connected.html and index.html remain unchanged.

Enter up to 20 unique numeric IDs separated by spaces, commas, newlines, semicolons or pipes; optional # prefixes are accepted. Click Load / preview orders. Review and deselect individual items. Missing or invalid records are reported separately. Cancelled records default to unchecked. Previewing does not change the draft. Append skips existing source IDs; Replace requires confirmation. Applying imports returns the document to draft status.

The optional supplier checkbox requires all selected records to identify the same supplier_id and resolves it through the active supplier list. Otherwise uncheck it and use supplier lookup/manual entry to choose the intended RFQ supplier, which need not be the currently assigned supplier. Existing suppliers are retained by default if already entered. Replacement requires the apply confirmation. No PartPulse supplier assignments are updated.

Prices and units for imported items are blank deliberately. Fill them from the approved supplier quotation. Existing freight, discounts, VAT, quotation reference and commercial terms are retained and must be reviewed. No PDF quote extraction is implemented. Requester names/building/cost centre are displayed only in the temporary review panel, not copied into imported descriptions or PDFs. Source descriptions and part numbers are copied as supplied and must themselves be reviewed for confidential content.

Compatibility: each imported item code is PP#4010 | PART-NUMBER. The PP#ID | prefix preserves references using the existing v1 JSON schema. Do not delete or edit the prefix. Editable descriptions, quantities and prices remain available; changing part numbers after the prefix is supported. The new workspace decorates the PDF preview with an Internal ID column and a source-ID summary. Old standalone pages show the prefix literally instead. Export/import retains markers because they are ordinary code strings. The document-reference field is independent and only auto-filled from source IDs if initially blank or #; it is not automatically renumbered on later edits. No production PO number is allocated.

Tests performed before publication: Node syntax check, core ID parsing/deduplication/limits/validation/source-marker JSON round-trip tests, and a mocked Chromium browser smoke test covering preview, apply, duplicate removal, common supplier fill, blank prices, source-reference PDF DOM and exclusion of requester names. These are not live authenticated tests or a full print-pagination test. Test on the VM, including login failure, mixed suppliers, missing IDs, cancel, append/replace, draft export/import, manual edits and PDF pagination, before operational use. The frontend role check supplements, but does not replace, the existing API's authorization; this addon does not strengthen or alter server permissions.

Rollback: stop using orders-connected.html and return to connected.html. Remove only the newly added files if desired. No production restart or database rollback is required. Same-origin code and iframes are not isolation boundaries. The inherited login token is not restricted to read-only permissions; this addon simply makes GET requests only.
